## 2. ПРОБЛЕМЫ (выявленные по research + анализ)

| #   | Проблема                                                                                | Источник                         |
| --- | --------------------------------------------------------------------------------------- | -------------------------------- |
| 1   | **Дублирование "Галереи"** — есть в desktop nav, в mobile "О нас", в footer "Компания"  | Анализ кода                      |
| 2   | **Cognitive overload** — мобильное меню имеет 7+ пунктов + 3 раскрывающихся секции      | NNGroup, cognitive load research |
| 3   | **Смешение логики** — "О нас" содержит Галерею (это не про компанию)                    | UX heuristic evaluation          |
| 4   | **Скрытые важные страницы** — FAQ, Площадки, Сертификаты глубоко buried                 | Task analysis                    |
| 5   | **Нет иерархии целей** — все пункты выглядят одинаково                                  | Figma 2026 trends                |
| 6   | **Mobile bottom nav не оптимален** — "Цены" и "Контакты" редко используются как primary | Mobile UX research               |

## 3. РЕКОМЕНДАЦИИ ИЗ RESEARCH (2025-2026)

### 3.1 Mega Menu Best Practices

- ✅ Группировать по **намерению пользователя** (intent), а не по отделам
- ✅ 5-7 видимых пунктов максимум
- ✅ Описания под пунктами (context)
- ✅ Визуальные акценты (иконки/фото)
- ❌ Избегать более 2 уровней вложенности

### 3.2 Navigation Psychology

- **Law of Parsimony:** меньше опций = больше конверсий
- **Recognition > Recall:** показывай, не прячь
- **Hick's Law:** время решения растёт логарифмически от количества опций
- **F-pattern scanning:** самые важные слева

### 3.3 Mobile Navigation (2025 consensus)

- **Bottom tab bar лучше hamburger** для первичной навигации
- Максимум **5 items** в bottom nav
- Hamburger OK для **secondary/tertiary** навигации
- Hybrid approach: bottom nav (primary) + hamburger (secondary)

### 3.4 Catering Industry Specifics

- Меню — #1 что ищут клиенты
- Контакты/заявка — всегда на виду
- Фото работ — критически важно для доверия
- Чёткие категории мероприятий

## 5. ПРИНЦИПЫ РЕАЛИЗАЦИИ

### 5.1 Информационная архитектура

1. **Чёткие категории** — каждый пункт имеет однозначное место
2. **Нет дублирования** — каждая страница доступна ОДНИМ путём из nav
3. **Progressive disclosure** — главное видно сразу, детали по запросу
4. **Consistent language** — одинаковые названия везде

### 5.2 Visual Design

1. **Визуальная иерархия** — размер/цвет отражает важность
2. **Достаточный contrast** — текст читаем (WCAG AA minimum)
3. **Touch targets** — минимум 44×44px для mobile
4. **Hover states** — понятная обратная связь

### 5.3 Interaction Design

1. **Hover открывает mega menu** (desktop), click — для перехода
2. **Click outside закрывает** dropdown
3. **Keyboard navigation** — Tab/Shift+Tab/Escape
4. **Focus trap** в открытых меню (accessibility)
5. **Smooth animations** — 200-300ms transitions

### 5.4 Responsive Breakpoints

- **Desktop (≥1024px):** Horizontal nav + mega menu dropdowns
- **Tablet (768-1023px):** Simplified horizontal + icon-only labels
- **Mobile (<768px):** Bottom tab bar + hamburger drawer
